# Voice Intent Normalizer 设计规格

日期：2026-07-29  
状态：待用户书面审阅  
建议技能名：`voice-intent-normalizer`

## 1. 背景

用户经常通过中文语音转文字向 AI 发布指令。通用语音识别对以下内容容易产生错误：

- 中文同音字和近音词，例如把“会话”识别为“绘画”。
- 英文产品名、模型名和工具名，例如把 `Codex` 识别为 `code X`。
- 行业术语、项目内部名称、人物名和品牌名。
- 快速进入中文语境的新兴 AI 词汇。
- 用户长期形成的个人表达偏好和常用对象。

本项目不接管麦克风或实时语音识别，而是在语音已经转换为文字并提交给 Agent 后，结合词库、项目内容、当前对话和个人记忆，推断用户真实意图。它修正 Agent 的理解，不修改已经发送的原消息。

## 2. 产品目标

### 2.1 核心目标

1. 用户选择目标平台并安装一次后，在该平台的不同会话和项目中自动生效，不要求逐次手动调用技能。
2. 对中文语音转写产生的同音字、近音词、英文音译和专业术语错误生成可靠候选。
3. 根据当前行业、当前项目、当前对话和个人偏好选择最合理的候选。
4. 低影响的高置信度错误静默纠正，重要专有名词给出轻量提示，关键歧义必须询问用户。
5. 从用户明确纠正和重复使用中积累可查看、可删除、可导出的个人词库。
6. 通过独立热点词库持续吸收新模型、新产品、新工具和新概念，不要求重新安装整个技能。
7. 默认在本地处理个人词库和项目词库，不上传私有内容。
8. 通过统一安装入口完成平台选择、能力检测和冒烟测试，不要求普通用户理解技能目录、Hook 或配置文件。
9. 让用户知道影响任务理解的重要纠正，并能用自然语言立即撤销、禁止或确认映射。

### 2.2 非目标

- 不替换或改造 Codex、ChatGPT、微信等应用自带的语音按钮。
- 不在第一版实现操作系统级输入法、麦克风接管或平台输入框插件。
- 不在说话过程中提供逐字实时转写。
- 不修改聊天记录中已经发送的用户原文。
- 不承诺读取所有原始历史会话。
- 不让模型仅凭一次猜测永久学习新映射。
- 不把项目术语、个人偏好或对话内容上传到公共热点词库。
- 不宣称发明了热词增强、上下文语音识别或专业词典技术。

## 3. 适用范围

本项目主要面向中文语音转写产生的指令文本。第一版采用“通用纠错核心 + 平台适配器”结构，首批支持：

- Codex 桌面端、CLI 和 IDE 扩展。
- OpenClaw（中文语境中常称“龙虾”或“小龙虾”）。
- WorkBuddy。
- 其他能够加载标准 `SKILL.md` 或 Agent Skills 包的桌面智能体，通过通用适配器安装。

正式产品名统一写为 `OpenClaw` 和 `WorkBuddy`。`Open Clow`、`Open Cloud`、`Work body`、`龙虾`、`小龙虾` 等表达作为可能的转写结果或上下文别名处理，而不作为平台标识。

通用核心是本项目的主要技能，包含纠错规则、词库、学习状态和安全策略。平台适配器仅处理技能安装位置、自动触发方式、配置格式、状态目录发现和卸载，不复制或分叉纠错算法。各平台共享同一词目格式；同一台设备上的多个适配器默认读取同一个个人词库和热点词库。

首版的直接用户价值是“让 Agent 按正确意图理解和执行”，不是“修改语音输入框中已经显示或发送的原文字”。README、安装界面和平台说明必须在首次使用前清楚说明该边界，不得使用“实时转写纠错”“输入框纠错”或“边说边改”等容易造成误解的描述。

需要文件系统写权限的能力包括：

- 安装全局启动规则。
- 保存个人词库和本地热点词库缓存。
- 在当前项目生成项目词库缓存。
- 写入用户明确确认的纠错映射。

在不允许文件写入的环境中，技能仍可基于内置词库、当前对话和当前可读项目内容执行一次性纠错，但不能持久学习。

## 4. 总体架构

系统由五个主要模块组成：

1. **通用技能入口**：通过共享 `SKILL.md` 说明何时调用纠错能力以及如何解释结果。
2. **平台适配层**：为 Codex、OpenClaw、WorkBuddy 和其他 Agent Skills 宿主完成安装、自动触发配置和卸载。
3. **分层词库系统**：管理基础、热点、行业、项目和个人五类词库。
4. **纠错引擎**：生成候选、评分、执行语义保护并作出纠错决策。
5. **学习与反馈模块**：管理候选、重复和确认状态，以及负向规则。

### 4.1 组件边界

```text
平台中的用户消息
  → 平台适配器（安装、触发、路径和能力检测）
  → 共享 SKILL.md
  → 通用纠错核心
      ├── 候选生成与评分
      ├── 五层词库
      ├── 项目扫描
      ├── 学习与反馈
      └── 安全策略
  → 平台 Agent 按纠正后的意图执行
```

适配器可以是单个配置文件，也可以是包含安装脚本、配置模板和平台说明的小目录。适配器不得维护自己的词库副本或修改通用纠错逻辑。

### 4.2 数据流

```text
用户提交文字
  → 当前平台的轻量规则判断是否疑似中文语音转写
  → 隐式调用 voice-intent-normalizer
  → 加载适用词库
  → 检测异常片段
  → 生成同音、近音、英文音译和术语候选
  → 结合项目、对话、领域和个人偏好排序
  → 应用安全边界
  → 按纠正意图执行并按需提示 / 询问用户 / 保留原文
  → 在满足学习条件时更新本地状态
```

## 5. 自动触发设计

### 5.1 共同触发原则

所有适配器都应尽可能实现以下标准模式：

- 把中文用户输入视为可能包含语音转写错误。
- 执行任务前进行低成本检查，只在存在异常信号时加载完整纠错流程。
- 低影响的高置信度错误可以静默执行，重要纠正按 5.8 节给出轻量提示。
- 会改变任务结果的歧义必须询问用户。
- “我说的是……”或“不是 X，是 Y”等明确纠正应交给学习模块。

平台不支持全局自动触发时，适配器必须明确标注能力降级，并提供最接近的项目级规则或手动调用方式，不得宣称已经实现全局无感触发。

### 5.2 Codex 适配器

安装器向 `~/.codex/AGENTS.md` 添加一个带开始和结束标记的短配置段。配置段要求 Agent：

- 把中文用户输入视为可能包含语音转写错误。
- 在执行前进行轻量检查。
- 出现同音、近音、英文音译、专业术语或语义断裂迹象时，隐式调用本技能。
- 低影响的高置信度错误可静默纠正，重要纠正按 5.8 节给出轻量提示。
- 会改变任务结果的歧义必须询问用户。
- 用户使用“我说的是……”等明确纠正结构时，把映射交给学习模块。

安装器不得覆盖用户已有 `AGENTS.md`，重复执行必须保持幂等。

Codex 严格模式可额外安装 `UserPromptSubmit` Hook。Hook 在每条用户提示提交时运行轻量检测，并只向 Agent 注入是否需要执行完整纠错的附加上下文。

### 5.3 OpenClaw 适配器

OpenClaw 适配器复用同一个 `SKILL.md` 和通用核心，支持以下目标位置：

- 个人跨 Agent：`~/.agents/skills`。
- OpenClaw 本地共享：`~/.openclaw/skills`。
- 当前工作区：`<workspace>/skills` 或 `<workspace>/.agents/skills`。

默认推荐个人跨 Agent 位置，以便在同一设备的多个 OpenClaw Agent 中使用。适配器应检测技能可发现性和有效配置，不直接读取或合并 OpenClaw 与其他宿主的原始历史会话。OpenClaw 会话中的当前上下文可以参与本次纠错；已确认映射写入本项目自己的共享个人词库。

### 5.4 WorkBuddy 适配器

WorkBuddy 适配器把共享技能核心打包为其“上传本地技能包”可接受的形式，并附带导入、启用、关闭和卸载说明。适配器应通过 WorkBuddy 的公开能力完成自动调用；如果某个客户端版本只能手动启用技能，必须在安装检查中报告该限制。

WorkBuddy 适配器不得依赖未公开的客户端文件、界面注入或绕过权限机制。由于 WorkBuddy 的技能包格式和触发能力可能随客户端版本变化，兼容性通过独立适配器版本和测试矩阵维护。

### 5.5 通用 Agent Skills 适配器

通用适配器面向可以识别 `SKILL.md`、但没有专用安装器的平台。它提供：

- 纯标准的技能目录。
- 平台无关的调用说明。
- 环境变量 `VOICE_INTENT_HOME` 用于指定共享数据目录。
- 自动触发能力检测清单。

通用适配器不承诺每个平台都能自动调用；只有完成平台专项验证后，平台名称才进入“已支持”列表。

### 5.6 严格模式

严格模式是可选项，不作为默认设置，原因包括：

- 配置复杂度更高。
- 每条提示都会运行检测脚本。
- 不同 Agent Skills 宿主对 Hook 的支持不一致。

第一版只在平台存在公开、稳定且可审计的提交前 Hook 时提供严格模式。Codex 支持该模式；OpenClaw、WorkBuddy 和通用适配器分别根据其公开接口声明支持、降级或不支持。

### 5.7 典型触发信号

- 中文句子语义断裂，但存在明显同音替代。
- 中英文混合片段出现异常空格、大小写或音译。
- 当前项目中存在与错误片段发音相似的准确名称。
- 输入包含“我说的是”“不是 X，是 Y”等自我纠正。
- 片段命中行业、热点或个人词库的已知别名。
- 输入包含大量专有名词或疑似语音填充词。

仅出现普通错别字且不影响理解时，不必加载完整技能。

### 5.8 纠错反馈

纠错反馈的目标是让用户能够建立信任，同时不把每条消息变成确认流程：

- 普通填充词、标点和不改变任务含义的高置信度纠正可以完全静默。
- 首次出现的专有名词、跨语言产品名或可能影响任务范围的纠正，显示一行简短提示。
- 中置信度或高影响歧义不使用提示代替确认，必须先询问用户。
- 同一映射在当前会话已经提示并被接受后，不重复打扰。
- 用户可以关闭非关键纠错提示，但不能关闭高影响歧义保护。

建议提示格式：

```text
已按 OpenClaw 理解（原转写：Open Cloud）
```

提示只说明本次 Agent 采用的理解，不声称修改了原消息。平台不支持独立提示组件时，使用简短文本回复，不依赖自定义界面。

### 5.9 首次使用体验

安装完成后必须立即运行一个不修改用户数据的测试：

1. 验证平台能发现技能。
2. 用内置语料测试 `open cloud → OpenClaw`。
3. 显示实际启用的平台、自动触发等级和共享词库位置。
4. 对能力降级给出普通语言说明和修复建议。
5. 提供一条用户可以亲自说出的测试句。

成功状态应表述为“已安装并通过测试”，而不是只表述为“文件复制成功”。如果只能手动调用，结果必须明确显示“已安装，但当前平台版本不支持自动触发”。

## 6. 分层词库

所有词库共享同一词目结构和匹配引擎，通过 `scope`、来源和权重区分作用域。

### 6.1 基础词库

基础词库随技能发布，包含稳定、跨行业的常见 AI 和软件术语，以及高频中文语音识别错误。

特征：

- 离线可用。
- 随技能版本更新。
- 更新频率低。
- 不包含用户或项目私有信息。

### 6.2 热点词库

热点词库包含快速进入中文语境的新模型、新产品、新工具、新概念、热门项目和高频英文缩写。

特征：

- 与技能逻辑独立版本化。
- 默认每天首次使用时检查一次更新。
- 只下载公开 JSON/JSONL 数据，不执行远程代码。
- 下载失败时继续使用上一个有效版本。
- 支持自动更新、手动更新、关闭更新和固定版本。

### 6.3 行业词库

行业词库按领域组织，例如：

- AI 与大模型
- 软件开发
- 产品设计
- 视频制作
- 金融
- 法律
- 医疗
- 电商和新媒体

技能根据当前项目文件、对话和用户显式选择激活一个或多个行业包。行业词库可以由社区独立贡献。

### 6.4 项目词库

项目词库只对当前文件夹或代码仓库生效。内容包括：

- 产品和客户名称。
- 文件名、目录名、模块名。
- 类名、函数名、组件名和 API 名称。
- 项目文档中的高频术语和缩写。
- 用户在当前项目内确认的专有映射。

项目词库是可重新生成的本地缓存，不自动提升为个人词库。不同项目之间不得互相泄露项目词目。

### 6.5 个人词库

个人词库跨项目生效。内容包括：

- 用户喜欢或经常提及的博主、作者、品牌和人物。
- 用户偏好的表达方式和中英文写法。
- 用户明确确认过的通用纠错映射。
- 跨会话重复出现且具有稳定意义的个人术语。
- 用户设置的禁止纠正规则。

个人词库只保存在本地，默认不提交到 Git，不参与公共热点词库更新。

### 6.6 词目格式

运行时词库使用 JSONL，每行一个词目，以便标准库解析、增量更新和社区审核。示例：

```json
{"canonical":"Codex","scope":"hot","aliases":["code X","code ex"],"phonetics":["kou-de-ke-si"],"domains":["ai","software-development"],"weight":0.9,"status":"curated"}
{"canonical":"OpenClaw","scope":"hot","aliases":["Open Clow","Open Cloud","龙虾","小龙虾"],"phonetics":["ou-pen-ke-lao"],"domains":["ai","agent"],"weight":0.9,"status":"curated"}
```

项目和个人词目可以增加来源信息：

```json
{"canonical":"WorkBuddy","scope":"project","project_id":"project-a","aliases":["Work body"],"weight":1.0,"status":"confirmed","source":"project-symbol"}
```

必需字段：

- `canonical`
- `scope`
- `aliases`
- `domains`
- `weight`
- `status`

可选字段：

- `phonetics`
- `project_id`
- `source`
- `first_seen`
- `last_seen`
- `use_count`
- `negative_aliases`
- `notes`

## 7. 项目词库生成

项目扫描器从以下公开项目表面抽取候选：

- 文件和目录名称。
- Markdown 标题和高频加粗术语。
- 代码中的公开符号、类名、函数名、类型名和枚举名。
- 包名、依赖名和产品配置中的非敏感标识。
- README、设计文档和用户指定的术语文件。

默认忽略：

- `.git/`
- `node_modules/`
- `vendor/`
- 构建产物和缓存目录
- 二进制文件
- `.env`
- 密钥、令牌和凭据文件
- 用户配置的排除路径

扫描器只保存候选词和必要的来源位置，不复制大段项目内容。项目词库生成失败时，纠错引擎继续使用其余词库。

## 8. 候选生成与评分

### 8.1 候选来源

- 已确认别名的精确匹配。
- 无声调拼音匹配。
- 常见前后鼻音、平翘舌和轻声近音规则。
- 英文拆词、连读、字母读音和中文音译别名。
- 字符编辑距离。
- 当前项目准确标识符。
- 当前对话中的高频实体。
- Codex Memories 或其他宿主记忆提供的个人偏好线索。
- 大模型基于整句语义生成的补充候选。

确定性脚本负责产生和排序可解释候选；大模型只负责补充语义判断，不得绕过安全边界。

“龙虾”等本身具有常用中文含义的别名必须依赖领域和上下文。在餐饮、动物等语境中不得自动替换为 `OpenClaw`；只有同时出现 AI、Agent、技能、桌面智能体等支持信号时，才可以提高 `OpenClaw` 候选权重。

### 8.2 评分因素

概念评分由以下因素组成：

```text
总分
= 发音相似度
+ 文本相似度
+ 当前领域匹配度
+ 当前项目匹配度
+ 当前对话匹配度
+ 个人使用频率
+ 用户确认权重
- 负向规则惩罚
- 歧义惩罚
```

实现阶段通过测试语料校准具体权重。用户确认映射和项目精确标识符拥有最高证据等级，但仍需经过危险内容保护。

### 8.3 决策等级

#### 高置信度

满足以下条件之一且无安全冲突时，可按纠正后的意图执行；是否显示提示由 5.8 节决定：

- 命中用户明确确认的映射。
- 命中当前项目准确名称，且发音高度相似。
- 候选与当前对话语义明显一致，领先第二候选的分差达到校准阈值。
- 英文错误转写命中热点或行业词库，且当前领域明确吻合。

#### 中置信度

候选合理但存在另一个接近解释时：

- 如果不同解释不会改变任务结果，可保留原文并继续。
- 如果不同解释会改变文件、功能或操作目标，必须询问用户。

#### 低置信度

不自动修改。按原文理解，或按正常任务澄清规则询问用户。

## 9. 安全边界

以下内容必须使用更严格的确认条件：

- 文件路径和目录路径。
- 命令行参数。
- 数据库、表、字段和环境名称。
- API 名称、代码符号和版本号。
- 金额、日期、百分比和其他数字。
- 删除、覆盖、发布、部署、提交、推送和权限变更等重要操作。

只有命中项目中的准确对象，或用户已经明确确认过映射时，才能自动替换这些内容。否则必须询问用户。

技能不得为了让句子更通顺而改变用户的任务范围、语气立场或事实主张。

## 10. 学习与反馈

### 10.1 学习状态

- `candidate`：只出现过或由模型推断，当前会话可用，不永久确认。
- `repeated`：跨会话多次出现，提高候选权重，但仍不是确定事实。
- `confirmed`：用户明确纠正或主动确认，可写入个人或项目词库。
- `rejected`：用户明确否定，写入负向规则，避免重复纠正。

### 10.2 明确纠正模式

以下结构视为强学习信号：

- “我说的是 X。”
- “不是 A，是 B。”
- “以后把 A 理解成 B。”
- “不要再把 A 改成 B。”

写入前必须判断作用域：

- 只属于当前仓库的名称进入项目词库。
- 跨项目的个人偏好或通用名称进入个人词库。
- 无法判断时默认进入当前项目词库，或在影响较大时询问用户。

### 10.3 用户控制

技能必须支持以下自然语言操作：

- 查看最近学到的词。
- 查看某个词的来源和匹配别名。
- 确认或拒绝候选词。
- 删除个人词目或项目词目。
- 禁止某个自动替换。
- 导入和导出个人词库。
- 清除指定项目的生成缓存。

普通用户不需要理解 `candidate`、`repeated`、`confirmed` 等内部状态。默认交互使用“待确认”“已学会”“不再纠正”等自然语言；内部状态只在诊断或高级导出中展示。

至少支持以下直接表达：

- “我说的是 OpenClaw，不是 Open Cloud。”
- “以后把 Work body 理解为 WorkBuddy。”
- “不要把龙虾改成 OpenClaw。”
- “撤销刚才的纠正。”
- “删除你学到的这个词。”
- “查看最近学到的词。”

“撤销刚才的纠正”必须同时撤回刚生成的学习记录或负向规则；如果任务已经执行，则说明只能撤销学习结果，不能假装已撤销外部操作。

### 10.4 宿主记忆

Codex Memories 或其他宿主提供的记忆能力可用于提供宽泛的个人偏好和跨会话线索，但不作为精确纠错映射的唯一来源。不同平台的记忆相互隔离，已确认词目必须写入技能自己的可审计共享个人词库。

## 11. 热点词库更新

### 11.1 更新流程

```text
当天首次触发技能
  → 读取 last-update.json
  → 超过 24 小时则获取远程 manifest
  → 比较词库版本
  → 下载新的数据文件
  → 校验 SHA-256 和 JSONL 结构
  → 写入临时文件
  → 验证通过后原子替换当前版本
  → 记录更新时间和版本
```

### 11.2 本地路径

默认使用平台无关的共享目录：

```text
~/.voice-intent-normalizer/
├── personal.jsonl
├── preferences.json
├── adapters/
│   ├── codex.json
│   ├── openclaw.json
│   └── workbuddy.json
├── hotwords/
│   ├── manifest.json
│   ├── zh-ai.jsonl
│   └── last-update.json
└── projects/
    └── <project-id>/
        ├── project.jsonl
        └── scan-state.json
```

用户可以通过 `VOICE_INTENT_HOME` 覆盖该位置。平台适配器只保存自身的安装状态，不复制个人词库。平台无法访问共享目录时进入隔离模式，并清楚提示该平台的学习结果不会自动同步。

### 11.3 安全要求

- 只接受受支持版本的清单和数据格式。
- 只下载允许的 GitHub Release 或固定官方域名。
- 验证 SHA-256。
- 拒绝包含脚本、路径穿越或未知字段类型的数据包。
- 先写临时文件，验证后原子替换。
- 保留最后一个有效版本以便回退。
- 网络失败、清单损坏或校验失败不得阻塞用户任务。
- 不上传任何个人、项目或对话数据。

### 11.4 更新边界

热点词库数据升级不要求重新安装技能。以下变化要求升级技能版本：

- 匹配算法变化。
- 数据格式发生不兼容变化。
- 安装器或 Hook 行为变化。
- 新增依赖或权限。
- 安全策略发生变化。

## 12. 安装、升级与卸载

### 12.1 安装

通用安装入口：

1. 识别或让用户选择 `codex`、`openclaw`、`workbuddy` 或 `generic` 目标。
2. 检查目标平台版本、技能目录和公开支持能力。
3. 安装共享技能文件或生成平台要求的本地导入包。
4. 创建平台无关的本地状态目录。
5. 由目标适配器写入带唯一标记的自动触发配置。
6. 仅在目标平台支持时提供严格模式。
7. 验证技能可被发现并报告实际触发能力。
8. 运行平台对应的本地冒烟测试。

默认安装流程只要求用户选择目标平台和是否启用自动热点更新。路径、Hook 和作用域使用安全默认值；高级选项折叠显示。安装器支持一次选择多个已检测到的平台，并逐个平台报告成功、降级或失败，避免用户分别执行多套安装流程。

### 12.2 升级

- 保留个人词库、负向规则和项目缓存。
- 分别升级通用核心和平台适配器；适配器升级不得改写共享词库。
- 迁移旧数据前创建备份。
- 数据迁移失败时回退技能版本并保留原数据。
- 不覆盖用户手动编辑的全局规则，只更新本技能标记范围内的内容。

### 12.3 卸载

- 删除所选平台中的技能目录或导入包。
- 只删除该适配器创建的标记配置和 Hook。
- 默认保留个人词库并询问是否一并清除。
- 卸载一个适配器不得影响其他平台的安装。
- 不修改其他技能、Hooks 或用户配置。

## 13. 错误处理

| 错误 | 行为 |
|---|---|
| 未安装拼音依赖 | 使用显式别名、文本和语义匹配，并提示完整能力不可用 |
| 项目扫描失败 | 使用基础、热点、行业和个人词库继续 |
| 热点更新超时 | 使用当前本地版本继续 |
| 热点文件校验失败 | 拒绝新文件并回退上一个有效版本 |
| 个人词库损坏 | 隔离损坏文件，使用最近备份并报告 |
| 没有写权限 | 以只读模式运行，不保存学习结果 |
| 平台不支持自动触发 | 报告能力降级并提供项目级或手动调用方式 |
| 平台技能格式发生变化 | 停止安装该适配器，保留通用核心和用户数据 |
| 候选分数接近 | 不静默纠正影响任务结果的片段 |
| 用户否定纠正 | 立即恢复原意并记录负向候选 |
| 用户要求撤销刚才的纠正 | 撤销本次学习记录；已发生的外部操作单独说明不可自动回滚 |

## 14. 技术选择

第一版脚本使用 Python 3.10+：

- 标准库处理 JSONL、哈希、网络下载、缓存和原子文件替换。
- `pypinyin` 作为完整中文拼音匹配的可选依赖。
- 缺少 `pypinyin` 时仍保留显式别名、文本相似度和模型语义判断。
- 不引入数据库；个人和项目词库均为可读、可审计的文本文件。
- 不在运行时静默安装依赖。

技能主体保持简洁，把详细词库规范、贡献规范和测试语料说明放入按需加载的 references。

## 16. 测试设计

### 16.1 单元测试

- JSONL 词目解析和校验。
- 拼音归一化和近音规则。
- 英文拆词、字母读音和音译别名。
- 作用域过滤。
- 候选排序和负向规则。
- 更新清单、SHA-256 和回退。
- `AGENTS.md` 标记段的幂等安装与卸载。
- 适配器检测、路径解析和共享状态目录。

### 16.2 语料测试

测试集至少覆盖：

- 中文同音字和近音词。
- 英文产品名的中文音译。
- 中英文混合输入。
- 项目专有名词。
- 用户自我纠正。
- 多个合理候选。
- 正常文本不应被修改。
- 文件路径、命令、数字和重要操作。

### 16.3 状态测试

- `candidate → repeated → confirmed`。
- 用户拒绝后生成负向规则。
- 个人词库跨项目生效。
- 项目词库不跨项目泄露。
- 无写权限和只读模式下不持久写入。
- 重复安装、升级和卸载不破坏用户文件。
- 在多个适配器之间复用个人词库，同时保持项目词库隔离。

### 16.4 故障测试

- 断网。
- 远程清单损坏。
- 热点词库哈希错误。
- 本地词库部分损坏。
- 无写权限。
- 缺少拼音依赖。
- 项目体积过大或包含大量二进制文件。
- 目标平台版本不受支持或技能包格式发生变化。

### 16.5 平台兼容测试

- Codex：桌面端、CLI 和 IDE 扩展中的技能发现与标准触发。
- Codex：可选 `UserPromptSubmit` Hook 的安装、触发和卸载。
- OpenClaw：个人、共享和工作区技能目录中的发现与调用。
- WorkBuddy：本地技能包导入、启用、调用、关闭和卸载。
- 通用适配器：标准 `SKILL.md` 不依赖平台专有字段即可加载。
- 各平台使用相同语料得到一致的候选与安全决策。

### 16.6 用户旅程测试

- 新用户通过统一入口选择一个或多个平台，不需要手工寻找技能目录。
- 安装完成状态包含技能发现、内置纠错语料和自动触发能力验证。
- 首次重要专有名词纠正显示简短提示，同一会话不重复打扰。
- 用户可以通过“我说的是……”“不要改……”和“撤销刚才的纠正”控制学习结果。
- 普通用户界面不暴露内部学习状态名称。
- 用户能够查看、删除和导出个人词库。
- README 和安装过程明确说明技能修正 Agent 的理解，不修改输入框原文。

## 17. 验收标准

第一版必须满足：

1. 已知词库错误的候选召回率不低于 95%。
2. 普通正确文本的错误自动修改率低于 2%。
3. 关键歧义不得静默选择错误答案。
4. 项目词库不得跨项目自动生效。
5. 用户明确纠正可以持久保存并在新会话中复用。
6. 每天最多自动检查一次热点词库更新。
7. 热点更新失败时继续使用上一个有效版本。
8. Codex、OpenClaw 和 WorkBuddy 适配器均通过各自的安装、发现、调用和卸载测试。
9. 安装、重复安装、升级和卸载不得破坏平台已有配置。
10. 卸载一个适配器不得删除其他适配器或共享个人词库。
11. 默认不上传项目、对话或个人词库数据。
12. 在缺少网络和可选拼音依赖时，技能仍能降级运行。
13. 不支持自动触发的平台必须明确报告降级，不得把手动调用描述为自动调用。
14. 安装器可以一次选择多个已检测平台，并分别验证安装结果。
15. 安装完成后提供可执行的测试句和通过/失败结果。
16. 首次重要纠正可见、重复纠正不打扰、关键歧义必须确认。
17. 用户可以用自然语言确认、禁止、删除和撤销纠正映射。
18. 所有公开说明均明确区分“Agent 意图纠正”和“输入框实时转写纠正”。

## 18. 开源定位

项目定位为：

> 面向中文语音转写指令的、跨桌面智能体、项目感知且可持续学习的 Agent Skill。

差异化重点：

- 不绑定某个语音识别引擎。
- 通用核心不绑定单个智能体平台。
- 首批提供 Codex、OpenClaw、WorkBuddy 和通用 Agent Skills 适配器。
- 统一安装入口降低跨平台配置成本。
- 自动扫描当前项目生成词目。
- 同时使用行业、热点、项目和个人上下文。
- 通过平台适配器尽可能实现跨会话无感触发，并如实报告能力降级。
- 采用可审计、可扩展的开放词库格式。
- 明确区分候选、重复、确认和拒绝，降低错误学习风险。

建议使用 Apache-2.0 许可证。公共词库贡献必须注明来源，不接受直接复制受限制的商业词典。

实施计划应按以下顺序展开：

1. 跨平台技能骨架、适配器接口和词目数据规范。
